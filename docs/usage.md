# 使用指南

[專案首頁](../README.md) · [架構](architecture.md)

Windows 使用 `AI-Agent.exe`；Linux／macOS 使用 `sh run.sh --no-browser`。首次啟動自動建立專案 `.venv` 並安裝依賴（包含 Blender MCP），之後依賴清單未變且必要模組齊全時直接啟動。兩者最後都進入根目錄的 `launcher.py`，設定統一讀取根目錄 `.env` 或環境變數。

Linux／macOS 需要 Python 3.10+ 與對應的 venv／ensurepip 支援；首次安裝及依賴更新需要網路。啟動準備集中在 `launcher/bootstrap.py`，不安裝到系統 Python，準備失敗不會啟動半套環境；下一次執行會重新嘗試。`PYTHON_EXEC` 可指定建立環境所用的 Python；若明確指定既有虛擬環境，則直接沿用該環境。

## 本機設定

第一次使用先複製 `.env.example` 為 `.env`，填入自己的 `OLLAMA_BASE_URL`、`DEFAULT_MODEL` 與 Token 配置。模型名稱需與 Ollama 已安裝的名稱一致；程式不下載模型。

設定優先順序：既有環境變數 → `.env` → 程式的通用預設值；命令列 `--port` 優先於 `SERVER_PORT`。本機啟動器固定使用 127.0.0.1，`SERVER_HOST` 用於直接啟動開發伺服器。

`.env` 是純文字設定，並非加密。`.gitignore` 已排除本機設定、Ollama 模型檔、資料庫與執行紀錄；公開時只保留 `.env.example`。若檔案已被 Git 追蹤，需先取消追蹤；忽略規則不會移除過去的提交紀錄。

核心入口：`app/core/agent.py`。工具的定義、Schema、驗證與結果型別集中在 `app/tools/registry.py`；內建工具清單在 `app/tools/__init__.py`，建立 Agent 時註冊一次。新增工具沿用 `tool_registry.register()`。

實作／對話模式用 finish_task 明確交付最終回答；普通文字只作進度或說明，不因「開始寫腳本」就結束。連續純文字最多補救兩次，仍未操作或結案則標為 no_tool_progress 並保留紀錄，不宣稱完成。一般問答可直接用 finish_task 回答，不強制建檔；原有 15 輪上限及額外統整仍保留。

前端使用原有 JavaScript，不新增建置流程；腳本依 index.html 順序載入，共用狀態集中於 app.js。HTML 不再包含整份聊天與地圖程式。

## 操作介面

聊天區只顯示訊息與輸入框；左側管理專案與對話，可收合。輸入框左邊「＋」選擇文件，也可拖入輸入框；文件擷取完成後顯示標籤，可在送出前移除；文件只解析文字。圖片可選擇、拖入或直接貼上截圖，上傳後顯示縮圖，按「送出」才交給目前的視覺模型。

右上「專案面板」預設關閉，集中為「檔案、記憶、規劃、執行、Log、Skill、MCP」：搜尋與互動地圖、L2 摘要與來源、SDD 與任務、背景工作與對話資訊、分類日誌、全域技能及外部工具連線。窄螢幕以覆蓋面板呈現。

任務執行時仍可切換／新增對話、瀏覽面板、上傳文件與撰寫下一則訊息；各對話分別追蹤任務與暫停狀態，切回可接續查看即時回覆。未送出的文字與附件在本次頁面開啟期間按對話保留。同一對話完成前不重複送出；執行中資料的移動、刪除與工作區任務修改仍受保護。

Markdown 文件預設顯示排版後的閱讀模式，可切換原始碼；搜尋結果指定行號時直接顯示原始碼。右上「暗色／淺色」可切換主題，選擇會保存在瀏覽器，首次使用跟隨系統。

聊天正文只由最終 `answer` 事件呈現一次；模型中途的普通文字以 `progress` 事件送入收合的「執行過程」，不接到正文。工具、思考與每輪說明均可展開查看，完整參數與回傳保留；失敗已有結論時不重複貼相同錯誤。SDD 保存後提供查看與實作入口。暫停只在處理時顯示；背景工作另有提示與停止控制。

## 對話隔離與紀錄

根目錄 `AGENTS.md` 保存使用者共用偏好；目前專案或對話子目錄的 `AGENTS.md` 才是局部規則。舊 `workspace/AGENTS.md` 不再自動套用到所有專案與一般對話。一般對話的工作區與歷史搜尋各自隔離；專案內的多個對話仍共享該專案工作區與 L2。

共用偏好由 `update_user_preference` 單項新增或取代，必須附上本次使用者訊息中的逐字引用，保留其他偏好並記錄修改前後與來源。是否為長期偏好由模型依 `prompts/preferences.md` 判斷；單次作品需求不得寫入 AGENTS.md，應留在對話、SDD 或專案記憶。下一輪主提示語重新讀檔，不需重啟；既有舊需求不自動清理。

舊版直接放在 `workspace/` 的檔案會保留，不自動搬移或讀進新工作區；請確認歸屬後自行搬到對應子目錄。已進入舊對話的任務內容不會自動清除。

log 分流到 `logs/projects/<專案ID>/agent.jsonl`、`logs/conversations/<對話ID>/agent.jsonl`，系統事件放 `logs/system.jsonl`。仍保留完整呼叫與錯誤，每檔 10 MiB、8 份備份；舊 `logs/agent.jsonl` 保留，不自動拆分。

「專案面板 → Log」可選目前專案／對話、只看此對話或系統；依 ALL、INFO、WARNING、ERROR 篩選，ERROR 也包含 CRITICAL。顯示最新 100 筆符合紀錄，可展開完整欄位與錯誤堆疊。每次至多掃描近期 4 MiB，涵蓋目前檔案及最多 8 份輪替備份；較早內容仍在來源檔。下載為目前來源整檔，不套用篩選。僅開啟、切換與手動更新時讀取，不定時輪詢；成功讀取不新增存取 log。

等級與類別獨立，可組合篩選「系統、模型、工具、MCP 連線、記憶與上下文」。工具類包含函式、背景工作、文件與 Skill 操作，MCP 的實際工具呼叫也歸此類；連線生命週期歸 MCP 連線。新紀錄寫入 category，舊紀錄依事件名稱分類。成功 GET／HEAD 查詢、重複 HTTP 存取與第三方套件的 INFO 訊息不再寫入；HTTP 失敗、工具完整參數／結果與錯誤堆疊保留。模型開始只記輸入數量、字數、工具名稱與設定，不在每輪重複保存整段上下文／工具 Schema；成功回應保留回答、呼叫與思考長度，失敗仍保留已接收內容供診斷。舊檔不刪除，畫面略過舊的成功查詢紀錄。

## 規劃與實作流程

- 預設：AI 自動依需求判斷處理方式；需要規劃時先保存 SDD，再等待按「開始實作」。
- 規劃：明確先建立 SDD，保存後等待按「開始實作」，不自動寫產品程式。

介面只保留這兩個模式。規劃時只提供探索與 SDD 工具（另允許共用偏好專用工具），不開放產品寫入與程式執行。`save_sdd` 成功後結束規劃，不繼續跑 Skill 的逐步確認流程。

「開始實作」出現在規劃回覆下方，也可從「專案面板 → 規劃」使用；按下後送出規格確認與實作要求，該次請求直接使用內部實作模式，跳過自動意圖判斷，讀取現有 SDD 並執行任務。選單回到預設，後續一般訊息恢復自動判斷。Skill 檔案保持不變。重新開啟對話後，面板依三份 SDD 檔案是否存在恢復按鈕。

只有預設模式的意圖判斷需要額外一次模型請求。每次處理維持 15 輪上限；第 15 輪已透過 finish_task 或成功規劃結案時直接交付，未結案才追加一次不開放工具的統整，第 15 輪回應為空也保留這次統整。按「開始實作」會另開一次處理，未要求時不執行測試。

結案資料集中在 `app/core/conclusion.py`，只收集本次執行的工具結果。強制統整最多六個短項目，不把讀取 Skill、瀏覽檔案或舊對話內容列為實作成果；模型無有效結論時，保底只顯示停止原因、本次已確認寫入／更新的檔案（最多三項）、工具失敗次數與下一步，不貼原始回傳、JSON 或歷史摘要。完整診斷仍保存在執行紀錄與 Log；保底不宣稱整體任務成功。

背景工作只在開啟對話／面板、相關工具完成、任務結束或手動更新時查詢。有工作執行中才每 10 秒追蹤一次，工作結束與隱藏頁面時停止定期查詢；連續失敗逐步延長到 60 秒。成功的工作清單／狀態查詢不寫入 JSON log，也不顯示於 Uvicorn 存取紀錄；失敗仍記錄。

每個背景工作在自己的項目下展開輸出、錯誤與下載連結，可分別收合。狀態更新保留既有展開內容；只有展開的工作讀取詳細輸出，已完成結果可重用，按重新整理才再次讀取。

## 圖片附件

支援靜態 PNG、JPEG、WebP；每則最多四張、單張最多 10 MiB／2500 萬像素。使用專案內的 Pillow 讀取，依方向資訊校正後，超過 2048 像素的長邊會等比例縮小，保存為 PNG。上傳本身不呼叫模型。

圖片保存在 `data/images/<對話雜湊>/`，以伺服器產生的 ID 引用；移動對話到其他專案不會丟失圖片。對話資料庫、工作上下文與 log 僅保存引用及必要資訊，送 Ollama REST 時才產生 `images` Base64 欄位。圖片可在重新開啟對話後預覽，後續問答也會帶入目前工作上下文中的圖片。

圖片用量另作保守估算並以模型回報校準；上下文壓縮保留最多四張近期圖片引用，較舊圖片仍保存在對話附件中。MCP 場景圖片也沿用此流程；文件內的圖片仍不解析、不做 OCR。

## 全域 Skill 安裝

在對話輸入「請幫我安裝這個網站的 Skill：網址」。預設模式將安裝 Skill 視為直接處理：先用 `read_web_page` 讀取介紹、安裝指令與連結，再用 `install_skill` 下載目標技能。網頁閱讀保留程式區塊與連結網址，也支援 Markdown。安裝來源支援公開 GitHub 倉庫／技能目錄、ZIP 和單份 SKILL.md；GitHub 使用[官方 ZIP 下載介面](https://docs.github.com/en/rest/repos/contents#download-a-repository-archive-zip)，不依賴本機 Git、Node.js 或 npx。

所有新增技能一律放在根目錄 `skills/<SKILL.md 的 name>/`，包含來源資料夾的腳本、參考資料與資產；既有同名技能保留，不直接覆寫。多技能來源回傳候選，Agent 依使用者要求選擇後再安裝，不自動全部加入。原有內附 Skill 與舊工作區 Skill 的載入方式保持不變；安裝只在實作階段提供，規劃模式不下載。

技能以暫存目錄完整寫入後才發布到全域目錄，失敗不留下可載入的半成品；下載最多 50 MiB，展開最多 100 MiB／3000 檔案，不接受越界路徑或符號連結。`SKILL.md` 需有有效 name、description，單檔上限 256 KiB。每個新技能附 `.agent-install.json` 記錄來源、時間與下載內容的 SHA-256，詳細成功／失敗仍記入目前專案或對話 log。

右側「專案面板 → Skill」列出兩個全域目錄（根目錄 skills/ 及舊 workspace/skills/），每項顯示名稱、description 一行用途與載入狀態。點選後在該項下方按需載入並渲染 Markdown；不把 YAML frontmatter 當正文，來源、位置與安裝時間另行收合。使用現有文件預覽的安全排版，不執行技能文件內的 HTML。僅開啟、手動更新與安裝工具完成時讀取，不定時輪詢。未記錄來源的內附／手動技能仍正常列出；此總表只檢查格式與載入順位，不保證外部依賴已具備。

安裝成功後下一輪主提示語自動重新發現，不需重啟。網站只用來解析安裝來源，不執行其 shell 指令或自動安裝額外依賴；單份 SKILL.md 不會憑空補齊腳本。需要登入、私人來源、只有動態網頁或非支援格式時會說明限制。額外 Python 套件、系統工具、MCP 與外部服務依賴需另行處理。

## 設定與執行資料

- `AGENTS.md`：跨專案共用的使用者偏好；不放個別作品的需求。
- `.env`：本機網址、模型名稱與參數，不提交、不打包。
- `.env.example`：可公開的設定範例。
- `prompts/`：系統預設提示語；由 `app/core/prompt.py` 動態組裝。
- `skills/`：原有 Skill 與新安裝的全域技能；既有技能不覆寫。
- `memory.db`：對話及專案資料庫，首次啟動時自動建立；乾淨交付版不附舊資料。
- `workspace/`：專案位於 `workspace/projects/<專案ID>/`；一般對話各用 `workspace/conversations/<對話ID>/`，不共用任務檔案。
- `data/`：圖片附件、上下文封存、工具全文與背景工作；按需要建立。
- `logs/`：執行紀錄；按需要建立。
- `runtime/`：Windows 內附 Python；Linux 使用專案虛擬環境或指定的 Python。
- `launcher/Launcher.cs`：Windows EXE 的啟動器原始碼；EXE 仍呼叫根目錄 launcher.py。

所有後端路徑由 `app/config.py` 統一定義，API 與靜態資源分別使用 `/api/`、`/static/` 網址。

## Blender MCP

右側「專案面板 → MCP」已預設 Blender，提供相容插件下載、連線、解除綁定與工具清單。MCP 連線成功與 Blender 場景可用分別顯示；需先在 Blender 安裝並啟用插件、按 Start MCP Server。

已結束的失敗連線可按連線直接重試；首次啟動失敗不留下新的實例綁定。同一服務的連線／中斷依序處理，避免重複啟動程序。啟動失敗保留巢狀例外及子程序 stderr 尾端，錯誤在該 MCP 項目下展開。Agent 位於遠端時，127.0.0.1 指遠端主機，跨機器部署需先建立對應轉送；本次修改未在使用者遠端 Blender 實機驗證。

內附官方 MCP Python SDK 與 Blender MCP 套件，不需 Node 或 uv。skills/blender/SKILL.md 提供操作流程；工具與原始 Schema 動態取得，只開放到目前綁定的專案／對話。同一 Blender 實例按任務排隊；規劃階段只開放明確配置的查詢工具。場景圖片沿用現有附件與視覺模型流程，呼叫紀錄沿用專案 Log。

設定預設讀取 mcp.example.json；自訂使用 mcp.json（不提交、不打包），環境差異放 .env。Linux 的 MCP 與 Blender 接入功能相同，由 run.sh 自動準備相容套件；Blender 應用程式及插件仍需在使用的電腦安裝並啟用。完整步驟與限制見 [Blender 接入說明](blender-mcp.md)。

## Skill 執行與空回應診斷

Skill 由 read_skill 載入工作說明，再依本輪實際提供的工具執行；技能名稱不代表存在同名函式。prompts/skills.md 只處理通用的技能／工具區分、資訊不足與環境假設；任務專屬流程、應詢問的欄位、製作方法及依賴由對應 Skill 定義，不放入共用提示語。原有 Skill 檔案不修改。

`read_skill` 回傳的 SKILL.md 或指定參考文件完整進入工作上下文，不套用一般工具輸出的單筆節錄門檻，避免文件讀完後又被截成頭尾、反覆用 read_tool_output 補讀。其他參考檔仍由模型按需要載入，不預先讀取整個技能目錄；整體達可用輸入預算 80% 時，仍由既有上下文壓縮保護處理，並封存壓縮前原文。這不代表無限長文件都能同時完整保留在模型中。

模型回傳 done=true 不代表一定有可用答案；model.end 記錄 done_reason、輸入／輸出 tokens、思考／回答長度與工具呼叫數。空回應以 WARNING 記錄，不再當成成功；沒有回答也沒有工具呼叫時，每次任務最多恢復一次模型請求，不重做任何已完成的工具操作，也不增加工具輪數。介面會顯示恢復狀態。

聊天輸入區可選「思考：低／中／高」，預設為中；低著重快速採取下一步，中適度分析，高深入評估關鍵方案與邊界情況。瀏覽器會記住選擇，每次送出時固定該次任務的程度，執行途中切換只影響下次送出。這與預設／規劃模式分開設定。

共用規則位於 prompts/reasoning.md，三種程度分別位於 prompts/reasoning/low.md、medium.md、high.md；所有 Skill 共用此引導。API 以 reasoning_level 傳入 low／medium／high，省略時為 medium，run.start 記錄所選程度。這只調整提示語，不改模型參數，不能保證精準的思考 tokens 或字元數；不以程式按思考長度中止串流，原有 Skill 檔案不變。

空回應恢復只補入通用提示語，保持原本的模型參數，不自動調低或關閉思考，也不額外探測思考控制選項。仍無有效結果時，run.empty_response 記錄診斷並明確結束；達 15 輪上限的額外結案保留原本流程，不在結案時恢復。

Ollama 的讀取逾時由 `.env` 的 `AGENT_MODEL_READ_TIMEOUT` 設定，預設 600 秒，修改後需重啟。這是等待後續網路資料的時間，不是整個任務的總時限；連線建立仍限 10 秒。逾時不自動重送請求或重做工具；介面會顯示中斷原因與已取得工具結果的摘要，保留上下文供後續接續，未接收完整的工具呼叫不會執行。延長等待不保證排除 Ollama 本身的停滯。

`model.failed` 保留例外類型、完整堆疊、已接收文字／思考／呼叫、讀取逾時配置、收到的行數及距最後一行的秒數（`last_line_age`，尚未收到任何一行時從請求開始計算）；最後一行不等於最後一個網路封包。若只看到 `ReadTimeout`，應對照同時段的 Ollama 服務紀錄、記憶體／顯存負載與連線狀態，無法僅憑它判定模型或硬體故障。

上述診斷有助區分輸出額度、只產生思考或模型工具格式相容性；沒有同次請求的模型紀錄，不能僅憑「空白內容」認定是哪一項。欄位與思考控制參考 [Ollama Chat API](https://docs.ollama.com/api/chat) 與[思考控制文件](https://docs.ollama.com/capabilities/thinking)。本次僅人工檢視程式，未執行測試或向使用者的遠端模型發送請求。

## 開發與更新方式

完整操作方式見 [啟動說明](../啟動說明.txt)。若要直接以模組啟動開發伺服器，於專案根目錄執行 `python -m app.web.server`；同樣會載入 `.env`。

更新時保留整個 app、prompts、skills 與 runtime。關閉舊服務後再啟動，並重新整理瀏覽器。

乾淨交付版不包含舊資料庫、專案測試檔、執行紀錄與 Python 快取。首次啟動會按需要建立執行資料；程式、套件、Skill 及操作說明均保留。

交付前使用 `python launcher/package.py`，或 Windows 的 `runtime\python.exe -B launcher/package.py`。此入口只打包列出的程式與必要套件，排除 `.env`、舊 launcher.ini、模型檔與執行資料；只附 `.env.example`。Git 忽略規則不會自動套用於手動壓縮，因此請使用這個打包入口。

另可用 `python launcher/package.py --platform linux AI-Agent-linux.zip` 建立 Linux 專用包：不附 Windows runtime 與 EXE，保留啟動準備、固定依賴清單、程式與 Skill；首次由 run.sh 建立該電腦適用的環境。
